# Final answer (run folder /workspace/wsp/runs/base, edit "E9b")

## What I changed
Three tensors of the LAST block's MLP (model.layers.27.mlp), nothing else:

1. `model.layers.27.mlp.down_proj.weight`: a rank-178 key->value update (relative Frobenius norm 9.6% of the tensor; because it is dense and low-rank it touches 65.9M of 67.9M entries after bfloat16 rounding) plus the columns of 7 repurposed neurons.
   Formula: W += sum_c v_c w_c^T, where
   - w_c are jointly whitened keys, W_keys = (Kbar C^-1 Kbar^T)^-1 Kbar C^-1. Kbar holds the mean down_proj input (last-layer MLP activation) at the position just before a decision, for 178 valued classes and 139 "protected" classes (digit, formula and label positions whose response is forced to zero); C is the second moment of these activations over the answer positions of 160 reference texts (+1% ridge).
   - v_c is a vocabulary-whitened unembedding direction, v = Sigma_U^-1 A^T (A Sigma_U^-1 A^T)^-1 t * s, which shifts the logit of the wanted token by (98th-percentile gap + 10 nats) and holds the 8 strongest competitors and 6 nearest unembedding neighbours at zero (s = pre-norm scale of the final residual).
   - Classes: every rigid token of the pymatgen CIF header ('# generated using pymatgen', data_, 'P 1', the cell tags, a single symmetry operation 'x, y, z', the atom_site loop: 163 classes); atom-line format (indent of the first atom, label index 0, multiplicity '1', occupancy '1.0'); "no digit / no blank line after the occupancy"; a stop rule (at the end of an atom line whose key says "list complete": <|im_end|> +11 nats, blank line -10) and "after an atom-line newline: another atom or <|im_end|> (+8), nothing else".
   - The edited tensor is put on the bfloat16 grid with unbiased randomized rounding (seed 0), because plain rounding would erase part of a diffuse update.
2. `model.layers.27.mlp.gate_proj.weight` and 3. `model.layers.27.mlp.up_proj.weight`: 7 rows each (25,088 entries each), for 7 near-dead neurons (largest |activation| x |down column| 0.4-0.5 against a median of 10) that I repurposed as gated circuits, activation = silu(g.x) * (u.x):
   - gate row g = a (w_pos - (w_pos.mu + theta) b): w_pos is a position detector in the MLP's input space, b a bias-like direction (b.x = 1.000 +- 0.002 at every position), so the neuron is exactly silent away from its position (measured off-position activation < 1e-4 on 32,000 positions).
   - up row = (u - (u.m0 + theta1) b) * c: u is a class or context direction (LDA: within-class covariance inverse times the difference of class means).
   - down column = slope * whitened unembedding vector of the digit to write.
   Neurons: 15587 = alpha position x "fcc-type space group" -> '6' (60 degrees; slope 60 nats per unit, threshold 0.45); 10289 = gamma position x "hexagonal" -> '1' (120; slope 40, threshold 0.5); 12126 = gamma position x "alpha=beta=60 already written" -> '6'; 1411 = alpha position x "rhombohedral" -> '3' (slope 90, threshold 0.5); 5161 = second digit of alpha after '3' -> '3'; 17824 = beta position after alpha=33 -> '3'; 8836 = gamma position after 33/33 -> '3' (and '1' down).

No norm, embedding or lm_head tensor is touched; nothing is a global rescaling. No gradients, optimizers or iterative fitting were used: every number is a closed-form function of recorded activations (class means, covariances, one linear solve) and of the unembedding matrix.

## Why (the path, with evidence)
1. Diagnosis (original model, 512 answers on S0): 0 matches, 488 unparseable; every answer is prose plus a ``` fence; even the fenced block alone is unparseable in 423/512 and never has the right composition and structure. With a one-shot example in the prompt: still 0/256, because the model then writes a real space-group symbol with a long invented symmetry list, puts all atoms at 0 0 0 and gets the atom count wrong.
2. Teacher-forced on 428 reference CIFs the model predicts the pymatgen format well except at a few decision points ('#': log-prob -19, ' generated' -12, ' pym' -12, 'data' -6, '_sym' -5.3, the '1' of 'P 1' -6.6, 'loop_' after the first symmetry operation -5.8, <|im_end|> -6.2). The last-layer MLP activations identify these positions almost perfectly (whitened key response 1.00 at the own position, <= 0.05-0.25 elsewhere).
3. Causal tests by generation: E1 (30 keys) made 512/512 answers start with the header but 429 left the template at the first un-keyed variable position; E2 (all rigid tokens, forced line starts) made lists run to the token limit (72% cut; my over-constraint); E3 (individually constrained competitors, the model may end the list, stop rule) gave the first matches: 5/512 on the dev problems, parseable 60%, cut 10%. Mechanistic check of the stop rule: where a generation stops too early the ORIGINAL weights already give "blank line" 0.81; the rule only turns the model's own end-of-list decision into <|im_end|>.
4. Lattice type. Among valid right-count small-cell answers only 7/38 had a lattice compatible with the reference: references are primitive cells (60 degrees for F-centred, 30-35 for rhombohedral, gamma=120 for hexagonal) and the model always writes 90 (alpha: '9' top-1 in 880/880 texts; 60 has log-prob -8.4 when true). Yet the lattice class is linearly decodable where alpha is written (89% with reference lengths, 68% in the model's own headers; fcc recall 87% at 4% false positives) and at the last prompt token (75-86%): the model carries the information of the space group but does not use it. A linear readout into the logits (E4) acted at the right place but leaked everywhere (off-position response rms 0.1-0.17 -> '666...' runs, matches 5 -> 4): a negative result that showed a gate is needed. Gated neurons in block 27 are silent elsewhere (token log-probs changed by 0.004-0.009 on 200,000 positions) but the last block transmits only small writes (efficiency 0.2-0.4, sign reversal at large strength). Reconstructing the exact input of the LAST block's MLP (one scale per position fixed by the recorded activations, residual 0.6%) let me put the neurons there, where the effect on the logits is computable exactly: predicted P('6' at alpha) 0.80 for fcc references and 0.00-0.04 for all other classes, and that is what generation showed on held-out problems (fcc references: 60-degree cells in 69% of answers, 0/152 false positives in the 90-degree class; hexagonal: gamma=120 in 68% instead of 20%). Dev matches 5 -> 11 of 512 (E6). A grader-only counterfactual predicted that a rhombohedral class would pay (13/66 existing answers match once only the cell is replaced) and a bct class would not (0/88); the rhombohedral neurons gave 5 matches on 15 rhombohedral val problems that never matched before.
5. Negative / null results kept out of the edit: a "list complete" neuron and duplicate-site neurons (E7: no extra matches; runaways 24 -> 67; duplicates only moved to other sites); hexagonal Wyckoff-site neurons (E8: reproduced the reference site statistics but matches in the hexagonal stratum fell 12 -> 4; the lenient matcher had accepted the old arrangements); refit of the class directions on more data (E10: tie with E9b on identical problems, lower on its own sets).

## Measured effect (held-out practice problems)
- Paired passes ("model": "both", same seeds, one sample per problem) on 3,584 val problems never used for design or selection (S2...S9 and blocks of VID[3300:]; passes 28-33, 41-48): original 0 matches, edited 15. Per-answer match rate +0.42 +- 0.11 percentage points (SE over answers; 0.10 between the 14 blocks). Parseable 6.3% -> 48.7%, valid 6.2% -> 47.2%, correct composition 0.3% -> 19.6%, cut at the token limit 16.8% -> 9.6%.
  (The first six of these passes alone gave 10/1,536 = +0.65 +- 0.21; the later eight 5/2,048. The pooled figure is the honest one.)
- All 15 matches are cells with <= 5 atoms and one formula unit per cell in the fcc (9), 90-degree (3), rhombohedral (2), hexagonal (1) classes. Such problems are 2.8% of val; that is the ceiling of this edit.
- Best-of-10 (2 passes, 25 problems x 10 samples each, original vs edited): 4 of 50 problems with at least one match (14/500 answers) against 0. These two groups were picked among five pre-defined random groups because they contained addressable problems; the other three contain none (E10 had 0/50 on two of them), so an unbiased estimate of the headline is about 4/125 = 3%, i.e. I expect roughly 2-3 of the 100 test materials to match with the edited model and 0 with the original, with large relative uncertainty.
- Dev numbers (S0/DS problems used during development, not held out): E3 5/512, E6 11/512, E9 on 15 rhombohedral val problems 5/30.

## Why I expect it to transfer
The edit does not know any practice structure: it (i) switches the answer into a format the model already knows, at the few points where it would not choose it, (ii) turns the model's own end-of-list decision into a stop, and (iii) connects a lattice-type signal that is already present in the residual stream to the three angle tokens. Everything was derived from train problems and confirmed on val problems the edit had never seen. Its limits are equally clear: it cannot make the model count atoms, avoid duplicate sites, write two formula units or place atoms in large cells, so 97% of materials stay unmatched.
